## 关键逻辑与说明

- 大屏按当前资产 UUID 合并指标，九台同屏，离线/异常优先、同级稳定排序。十秒刷新，指标九十秒、心跳三百秒为新鲜度阈值，缺失值不补零；可进入对应主机监控。
- Agent 源码固定 LF，避免 Windows 签出改变部署校验和。原端口、Token、监听地址和防火墙配置保留。
- 电费按逐日电量与实际单价估算可用天数，自然月星期日历排列。通知目标独立配置，支持标题/正文模板及批量管理。修复 Python 字符串转义导致整页 JS 失效的问题。
- 服务操作集中在管理弹窗，统计只计可见服务；删除标记防止来源刷新重建入口，历史保留。
- 模型用量仅展示上游实际提供字段；凭据/地址变更后使用新的历史作用域。Go/DeepSeek 真实连接需配置对应 Key，未公开数值不填零。

## 部署与回滚

- Agent：`deploy/k8s/opscenter-agent-2.6.4.patch.json`。
- 大屏：`deploy/k8s/opscenter-host-screen-5.5.17.patch.json`。
- 模型：`deploy/k8s/opscenter-model-usage-1.1.0.patch.json`、`opscenter-model-usage-web-1.1.0.patch.json`。
- 补丁引用版本化 ConfigMap；新环境先创建对应源码/静态包 ConfigMap，再应用补丁。大 bundle 使用 create，避免 client-side apply 的大 last-applied 注解。
- 扩展 Dockerfile 基于历史 backend 镜像，单独构建不会包含本轮后端源码；重建需从本标签更新 backend 并打包模块源文件，或使用已验证的 ConfigMap 覆盖方式。
- `metric-history-retention-cronjob.yaml` 为此前运行的分批清理配置，涉及历史删除；本次仅保存代码，不应用。
- 生产备份路径见来源索引，真实配置及数据库备份不纳入 Git。
